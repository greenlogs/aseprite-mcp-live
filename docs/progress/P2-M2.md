## 实际完成了什么

scripts/build_release.py 用 uv/hatch 构建 wheel/sdist，生成确定性根布局 .aseprite-extension、生产 requirements.txt、manifest 和摘要。服务、Lua 握手和扩展清单版本一致，握手显示/核验扩展版本；协议 v1。源码白名单、包内容和 MIT/NOTICE 检查排除 Aseprite、配置、会话及构建缓存。

建立 Windows 安装、实际 stdio 配置、连接/创作/保存/历史规则、升级/卸载、故障与发布说明。check_docs.py 验证本地链接及锚点、真实脚本入口和模块索引；Windows CI 配置运行无 Aseprite 的故障契约及构建，不代替 GUI。verify_install.py 独立脚本只依赖发布文件/SDK/Pillow，能复制到新目录由安装环境直接运行，不导入开发目录源码。

隔离验收发现 SDK 1.6.0 额外包装 ToolError，已在 ContractServer 兼容边界返回可直接 JSON 解码的 Result/isError；参数错误同样结构化。最终复核修正实时重连误清 CLI 去重回执，新增回归及真实安装后重放检查。另补直接调用 CLI 后端却传入实时目标时的 INVALID_TARGET 契约，避免属性异常；服务仍禁止后端自动降级。

独立安装不使用开发目录产品源码；解释器由 uv 的隔离 Python 提供。扩展采用安装文档中“解压 ZIP 到配置目录”的正式可用方式，不声称自动点击了安装管理器或权限提示。MCP 实际客户端为 Python SDK，图片由 HTML/Edge 显示；没有擅自改动个人客户端或 Codex 的 MCP 配置，也不宣称 Codex 原生已配置。

初轮问题如实记录：uv pip sync 不接受 -r，文档改为位置参数；首次隔离客户端在解析 SDK 前缀时失败，修正兼容边界后通过；SDK Windows 管道析构噪声经脚本 gc/短事件循环刷新消除；Edge 沙箱内 GPU 进程启动失败，使用同一独立 profile 的授权本地渲染通过。初轮日志 .work/P2-install.log、P2-install-v2.log/v3.log 保留，不计入最终通过数。

## 接口与兼容变化

hello 可选 extension_version、状态 service_version/extension_version，提供不匹配版本时 VERSION_MISMATCH。旧开发扩展未提供时显示 null 并建议更新。ContractServer 针对固定 SDK 的异常链解包，升级 SDK 须复测；严格 Result 校验不接受任意文本冒充成功。CLI 回执跨实时重连不再丢失。协议、样例、架构和安装文档同步。
