# P2 · 稳定性与首版发布

先读[执行约定](../README.md)、[P2 总结](../../progress/P2.md)和必要前置交接。阶段目标：Windows 用户可按公开文档安装服务和扩展，可靠完成实时核心闭环，同时明确 CLI 兼容范围。

共通边界：P1 集成已验收；此阶段建立可发布产物和证据，不自动推送、创建远程仓库或发布 Release。首版不要求全部上游工具实时可用。

<a id="p2-m1"></a>
## P2-M1 · 错误与状态管理

**前置与必要读取：**P1-M3 和 P1 集成已验收；读取其报告、实际请求队列、会话注册、事件监听、CLI 执行器和核心工具测试。

**执行提示词：**围绕已有纵向闭环补齐失败与恢复路径，重点验证写入只执行一次、目标不漂移及超时不误报。保留原始错误证据，同时向用户提供可行动的结果。

- 实时实现：完善断线、重连、文档关闭、人工编辑并发、重复/迟到消息、UI 正在繁忙和扩展重载的处理。执行前核验文档修订；失效活动上下文不能被无声复用。已完成请求在会话内返回缓存结果；未确认的写入返回结果未知，重新获取状态后由调用者决定下一步。
- CLI 实现：替换阻塞事件循环的执行路径，设置超时，捕获程序缺失、无法启动、非零退出、脚本错误和解码失败；清理本次启动的进程与临时文件。同一磁盘文件操作串行，并对读取后被外部修改的目标给出冲突，不静默覆盖。
- 接口/兼容：沿用统一错误分类，将 MCP 失败标记与结构化错误同步；日志不混入 stdio 协议，不记录会话校验材料或图像大负载。对改动后的错误、超时和去重规则补充契约样例及兼容说明。
- 性能边界：分别测量 CLI 启动/打开/保存和实时排队/执行/编码耗时，据此复核批次、消息与预览上限。小请求不得被长期阻塞；大原子批次超过预算明确拒绝，不拆成多个已提交事务。没有真实对照不宣称加速倍数。
- 验收：故障注入覆盖断线前后执行、重复标识、修订冲突、目标关闭、事件风暴和超时清理；真实编辑器验证人工切换文档、修改图层、撤销、重连后旧请求失效。确认连接失效不会触发 CLI，另跑上游相关测试及中文路径、并发文件修改回归。记录模拟与真实验证的区别。

**交接与状态：**执行后写 `docs/progress/P2-M1.md`（实施时生成或更新），同步[阶段总结](../../progress/P2.md)、根计划、结构和接口文档；已验收模块默认本地提交，不推送。

**下一步：**[P2-M2](#p2-m2)，以故障处理后的实现制作可复现安装包和首版验收说明。

## P2-M2 · 安装打包及发布验收

**前置与必要读取：**P2-M1 已验收；读取其报告、依赖与许可、真实服务启动方式、扩展包内容、现有测试说明及核心闭环步骤。

**执行提示词：**提供干净环境可用的 Python 服务安装、扩展包和中文使用说明，形成首版发布候选。发布状态只能来自实际构建和测试结果。

- 实现：建立基于 `uv` 的安装与 stdio 启动入口、使用占位安装位置的 MCP 配置示例、`ASEPRITE_PATH` 配置及扩展地址/会话设置步骤。将扩展打包为 `.aseprite-extension`，明确版本和协议对应关系；记录服务与扩展升级、卸载及不兼容诊断方式。
- 公开文档：补齐安装、测试、贡献、故障排查和发布说明；README 只展示已验收能力及跳转链接。说明实时/CLI 启用方式、保存与覆盖规则、撤销对象、批次限制和平台状态。真实演示产物可加入，但须记录生成步骤及来源。
- 发布检查：复核 MIT 和第三方声明，检查分发清单，排除 Aseprite 程序、个人配置、恢复会话、凭据及临时输出。建立对应的测试/打包 CI 和轻量文档链接、入口与结构同步检查；真实 GUI 验收仍单独记录，CI 模拟通过不能替代。
- 接口/兼容：客户端配置使用实际已建立的入口，不能复制上游路径当作本项目安装命令；不虚构仓库 URL。Windows v1.3.7 为必验组合，其他系统与版本按证据标注。原始 Lua 和高级工具配置不能默认混入实时核心能力集。
- 失败与边界：端口占用、软件路径错误、Python 不满足版本、扩展版本不兼容和依赖安装失败都有排查入口。只有安装文档、构建日志或包文件任一存在，不足以认定发布验收通过。
- 验收：使用不依赖开发目录源码的干净 Windows 环境或隔离安装目录，按文档安装并运行服务、安装扩展、配置真实 MCP 客户端；完成未保存文档读取、批量编辑、直接预览、撤销/重做、显式保存及重连。复跑 CLI 回归；核对扩展压缩包结构、服务分发内容和所有文档链接。

**交接与状态：**执行后写 `docs/progress/P2-M2.md`（实施时生成或更新），同步阶段总结、根计划、结构、README 的实际能力及安装入口；已验收模块默认本地提交，不推送。

**阶段集成验收：**记录完整干净安装过程、实际软件/客户端版本、构建产物和测试结果，证明全部首版功能可用、错误路径明确、分发内容合规且文档对应真实入口。未完成真实客户端和软件验证时保持未验收，不能宣布首版可发布。

**下一步：**集成通过后记录“首版候选已验收，尚未发布”的真实状态；远程发布按用户授权处理。高级功能进入 [P3-M1 · 上游工具兼容清单](P3-高级能力迁移.md#p3-m1)。

P2-M1 已采用接口：Request.expected_file_revision/data.file_revision、Limits.max_batch_seconds；取消只取消等待，未知写入先刷新状态，详情见 [协议补充](../PROTOCOL.md#p2-m1-故障与兼容补充)。P2-M2 构建须同时包含新服务和扩展。
