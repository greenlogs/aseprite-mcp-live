# P1 · 实时核心闭环

先读[执行约定](../README.md)、[P1 总结](../../progress/P1.md)及必要前置交接。阶段目标：用户能对当前未保存画布发出编辑请求、直接看到图片并撤销/重做。

共通边界：P0 集成验收通过；使用 [P0-M2 协议 v1](../PROTOCOL.md) 和[可校验样例](../protocol-v1.examples.json)，复用 `core/protocol.py`、`config.py`、`execution.py` 与 `server.create_server()`。首版绘制仅支持 RGB 普通图层，实时操作不隐式保存，不以全部上游工具数量作为完成标准。

<a id="p1-m1"></a>
## P1-M1 · 扩展连接

**前置与必要读取：**P0-M2 及 P0 集成已验收；读取其报告、[架构说明](../ARCHITECTURE.md)、[插件与 WebSocket 参考](../../REFERENCES.md#官方资料)。

**执行提示词：**建立 Python 本机 WebSocket 桥接和 Lua 扩展，完成真实 Aseprite 内的握手、状态查询与请求往返。扩展由 `package.json` 注册，使用 `init(plugin)`、`exit(plugin)` 管理生命周期，提供连接/断开菜单和配置。

- 实现：使用 P0 的协议、版本及会话校验，提供 `get_connection_status`；连接对象和监听器保持可靠引用，断开、退出或重载清理资源。错误反馈可见，服务地址和会话配置有明确入口。复用 Executor 已有请求关联/基础去重，补充扩展端去重和线上握手 hello/welcome，不推迟到有写入后再考虑；实际 Backend 必须绑定工具正在使用的同一个 Executor。
- 接口/兼容：扩展主动连接回环服务；兼容 v1.3.7 WebSocket 回调参数。握手能力根据实际探测填写，拒绝协议不兼容与第二个活动会话。服务器 stdout 保留给 MCP stdio，日志走独立通道。
- 失败与边界：服务器未启动、端口冲突、配置错误、校验失败、重连、未知消息和扩展退出均不会触发文件操作。旧会话请求不得在重连后的新会话执行。
- 验收：模拟桥接验证握手拒绝、版本不兼容、重复请求和错误结构；真实 v1.3.7 完成连接、无副作用请求往返、断开、重连及退出。重复启停不增加重复监听或残留端口，记录实际步骤和版本。

**交接与状态：**执行后写 `docs/progress/P1-M1.md`（当前未生成），同步[阶段总结](../../progress/P1.md)、根计划、结构和架构；默认验收后本地提交，不推送。

**下一步：**[P1-M2](#p1-m2)，在已验证的连接上建立文档注册及可撤销编辑。

<a id="p1-m2"></a>
## P1-M2 · 文档及事务编辑

**前置与必要读取：**P1-M1 已验收；读取其报告、协议类型、桥接分发和上游相关绘图/图层代码。

**执行提示词：**实现 `list_documents`、`get_document_info`、`create_sprite`、`apply_operations`、`save_sprite`、`undo` 和 `redo`，操作当前编辑器中的明确文档。首版批次操作及命名沿用架构约定。

- 实现：建立会话内文档/图层注册表，监听内容变化和活动上下文；图层重名、重命名不影响标识。CLI 索引路径不能直接用于实时对象；P0-M2 实测重复枚举的 Lua userdata 不宜直接作为哈希表定位键，注册表需用对象相等比较等实际可用方法验证。请求执行前核对预期修订，并按文档串行处理；用户切换文档不改变请求目标。人工编辑和撤销/重做更新修订信息。
- 事务：批次先完整校验，再通过 `app.transaction()` 提交；复制图像修改后赋回 Cel，正确处理画布坐标、Cel 偏移、空 Cel 和图层透明度。一个批次一次撤销，异常时回滚所有支持的编辑，保存独立执行。
- 接口/兼容：新建文档为 RGB；索引/灰度绘制、锁定或非普通目标图层明确拒绝。未命名保存要求路径；覆盖需显式允许。撤销作用于目标文档当前最新历史动作，并告知结果，不宣称只撤销 AI 的操作。
- 失败与边界：关闭文档、过期会话、失效图层、无效帧、修订冲突、越界坐标、超限批次和保存失败返回错误且不误改别的文档。重复变更请求不得重复执行；超时后不自动重发。
- 验收：真实创建未保存文档、人工绘制后读取，创建重名图层并精确定位，单批绘制多个图形；比较像素和修订，撤销/重做与预期一致。注入批次后续操作失败，确认前面操作回滚；验证偏移 Cel、空 Cel、中文保存路径及拒绝覆盖。模拟测试补充难以稳定触发的竞态，不替代真实撤销验证。

**交接与状态：**执行后写 `docs/progress/P1-M2.md`（当前未生成），同步阶段总结、根计划、结构及接口说明；默认验收后本地提交，不推送。

**下一步：**[P1-M3](#p1-m3)，为同一修订和帧生成模型可直接查看的图片。

<a id="p1-m3"></a>
## P1-M3 · 图片预览与集成

**前置与必要读取：**P1-M2 已验收；读取其报告、统一结果类型、上游导出及分析合成代码、MCP SDK 实际图片内容接口。

**执行提示词：**实现 `get_preview`，将当前内存文档指定帧/区域合成为 PNG，通过 MCP 图片内容直接返回，而非要求客户端额外打开磁盘路径。

- 实现：透明背景、整数最近邻放大和区域预览；元数据包含目标、实际修订、帧号、区域及缩放。使用副本或独立图像合成，不能改变源文档、活动上下文、修改标记和撤销栈；临时资源在成功、失败后均有清理。
- 接口/兼容：沿用 P0-M2 的图片消息与结果结构；预期修订过期返回冲突，避免将旧画面当作最新结果。遵守像素和图片体积上限，超限给出缩小范围或缩放的明确说明。
- 失败与边界：透明图层、非零 Cel 偏移、多帧、多图层、无效区域、关闭文档和编码失败均有测试。不将“已返回图片数据”直接等同于“客户端显示成功”。
- 验收：比对 PNG 解码后的像素、透明度、尺寸及区域原点，放大图不得平滑插值；确认预览前后文档内容、保存状态、活动上下文和撤销历史不变。用至少一个真实 MCP 客户端确认图片可见，记录客户端与软件版本，执行“看图—编辑—再看图”。

**交接与状态：**执行后写 `docs/progress/P1-M3.md`（当前未生成），同步阶段总结、根计划、结构及能力说明；默认验收后本地提交，不推送。

**阶段集成验收：**真实 MCP 客户端连接扩展，读取人工编辑的未保存画布，提交一批编辑，直接获取对应预览，执行一次撤销和重做并再次查看；全过程目标正确、源文件不隐式保存。记录真实证据，回归 P0 的 CLI 路径。

**下一步：**阶段通过后进入 [P2-M1 · 错误与状态管理](P2-稳定性与首版发布.md#p2-m1)，系统验证故障与状态竞争。

实施补充：P1-M2 已冻结 save_sprite 仅写原生 .aseprite/.ase 绝对路径；revision 为事件计数，回滚可能推进，不应推算下一修订。JSON userdata 的对象用 pairs、数组用 ipairs 递归转换，避免 API 28 编码差异。
