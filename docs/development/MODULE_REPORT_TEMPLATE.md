# 模块交接模板

复制本模板为 `docs/progress/<模块编号>.md` 后填写真实事实。标题替换为实际模块编号与名称；未执行项写明原因，不复制任务要求充当完成记录。模板本身不代表某个模块已经开始。

## 状态

- 模块编号与名称：填写实际值。
- 状态：未开始 / 进行中 / 阻塞 / 已实现待验收 / 已验收。
- 更新日期：填写实际日期。
- 前置：填写模块编号及已生成报告的相对链接。
- 根计划勾选：仅实现且验收通过后为已勾选。

## 实际完成了什么

填写实际能力、关键文件与入口、复用接口、设计原因和未完成范围。区分代码完成与验收通过。

## 验收证据

| 验收项 | 实际命令或手工步骤 | 环境与结果 | 证据位置 |
|---|---|---|---|
| 填写实际验收条件 | 填写可重复步骤 | 通过 / 失败 / 未执行 | 日志、截图或本报告内的完整记录 |

分别记录模拟测试、真实 Aseprite 测试和客户端显示验证。未执行项及原因必须写明；截图、日志链接仅指向实际存在且允许入库的内容。

## 接口与兼容变化

记录公共工具、桥接格式、依赖、能力及版本影响，说明已同步的契约与回归；没有则写“无”。

## 结构变化及同步情况

- 新增、删除、移动的模块，或职责、依赖、启动/测试/打包入口变化：填写实际变化，没有则写“无”。
- `docs/PROJECT_STRUCTURE.md`：记录同步内容、复核日期和模块编号；无结构变化也确认是否需要复核。
- README、架构及执行约定：记录实际更新，没有则写“无”。

## 遗留与阻塞

记录问题、影响、复现或修复入口、是否阻止勾选；没有则写“无”。注明测试或环境缺失，不掩盖回归。

## 下一模块该做什么

- 下一模块：填写实际编号；当前未通过时先修复当前模块。
- 提示词：链接到实际阶段文件及模块锚点。
- 必要读取：仅列直接依赖的报告和相关代码入口。
- 接续任务：写出可立即执行的具体任务及可复用接口。
- 注意事项：写明实际兼容限制和必须先修复的问题。

## 状态同步与提交

- [ ] 已更新阶段完整总结和根计划，状态如实一致。
- [ ] 已核对结构变化及相关文档同步，实际与规划结构分开。
- [ ] 若为阶段最后模块，已记录阶段集成验收及下一阶段接续；非最后模块注明不适用。
- 本地 Git：记录实际提交标识与主题，或未提交原因；不推送。不要为回填提交标识制造无意义的第二次提交，可先记录预定提交主题。
