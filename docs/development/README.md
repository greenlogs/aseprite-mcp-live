# 开发执行约定

## 目标与技术决策

项目面向使用 MCP 客户端进行像素画创作的用户，目标是让 AI 与用户在同一个 Aseprite 文档中连续编辑。首版闭环为连接、读取未保存文档、批量绘制、图片预览、撤销和重做。

基于 diivi/aseprite-mcp 改造，使用 Python 3.13+、`uv`、Python MCP 服务及 Lua 扩展。保留磁盘文件 CLI 后端；实时模式通过本机 WebSocket 控制当前编辑器，不静默降级到 CLI。详细边界见[架构说明](ARCHITECTURE.md)。

Windows 和本地 Aseprite 1.3.7 / API 28 为首版真实验收基线；其他系统、更新版本分别记录测试状态，不能按代码看似跨平台就宣称支持。运行配置使用 `ASEPRITE_PATH`，环境事实及官方来源见[参考资料](../REFERENCES.md)。

中文文档、英文接口与代码标识。保留上游 MIT 许可和版权；新增代码默认 MIT。未建立本项目远程地址前不生成安装徽章、下载地址或问题反馈链接。

## 按需读取与执行

读[根执行计划](../../EXECUTION_PLAN.md) → 本文件 → 当前模块提示词 → 本阶段总结和必要前置报告，再查相关实现。一次处理一个模块；不默认读取全部提示词、所有实现或全部历史。

前置未验收先完成前置。所有模块编号保持稳定，新增任务使用未占用编号并同步索引。当前阶段必须可直接实施；P3 的迁移批次由启动时清单决定，需先细化再实施。

P0 开发已验收；用户后续单独授权初始化 Git 并创建一次本地提交。远程设置、推送及发布仍需当次授权。

## 状态、交接与结构同步

`- [x]` 仅表示已实现且验收通过；`- [ ]` 表示未完成或未验收。状态可记录为未开始、进行中、阻塞、已实现待验收、已验收。

每模块结束按[交接模板](MODULE_REPORT_TEMPLATE.md)写 `docs/progress/<模块编号>.md`，记录真实完成、验收、接口变化、遗留问题与下一具体任务；失败、暂停或阻塞也交接。计划生成时不提前创建独立模块报告。

同步更新模块交接、`docs/progress/<阶段编号>.md` 和根执行计划；根计划每阶段只保留一句事实短总结和完整总结链接。阶段最后模块执行集成验收，相关回归失败则退回未勾选；全部模块及阶段集成通过才宣布阶段验收。

[动态项目结构](../PROJECT_STRUCTURE.md)是目录、职责和入口的唯一结构说明。新增、删除、移动模块或改变职责、依赖及启动/测试/打包入口时，同次交付更新其实际树、规划区和复核记录；交接中填写同步情况，无变化则写“无”。架构接口变化另同步架构说明，不能只修改目录树。

## 证据与验收

验收记录必须包含命令或手工步骤、实际环境、预期及实际结果、证据位置。模拟验证、真实 Aseprite 验证和客户端显示验证分开记录；环境缺失写“未执行”，不能用模拟结果替代。

- P0-M1 依据导入版本建立可重复的 `uv` 依赖和测试命令，在报告与测试说明中写明真实命令，不提前声称 `uv run pytest` 可运行。
- P0-M2 建立操作、结果、错误和版本能力接口，形成契约测试及一条真实 CLI 验证。
- P1 真实验证未保存文档编辑、正确撤销、图像反馈；P2 补充故障、打包和干净安装验收。
- 性能测试分别记录启动、读写和编辑耗时；没有对照数据不写加速倍数。
- 测试和构建产物置于明确的临时目录或忽略目录；公开文档不得包含凭据、个人会话数据或不必要的机器信息。

P0 建立正式测试说明，P2 建立安装、故障排查和发布说明；创建后同步本入口及项目结构。不要提前链接尚未生成文件。

## 版本管理与发布

2026-10-21 按用户单独授权初始化本地 Git，首次提交纳入已验收 P0 基线。忽略规则排除软件、配置、环境和测试产物，沿用已有提交身份，不更改全局 Git 配置；远程设置、推送及发布按当次授权处理。

已验收开发模块默认提交一次本地 Git，包含本模块实现、测试和文档；显式选择文件，不夹带他人修改，不自动推送。单独生成计划无需提交。

入库前忽略本地 `Aseprite/`、个人配置、恢复会话、凭据、临时输出和构建产物；不删除本地软件或个人文件。上游自带源码、必要测试资源及已许可示例不能被过宽规则误排除。

P2 是首发交付点。发布验收通过只表示产物可发布；不自动创建 GitHub 仓库、不推送、不发布 Release。P3 首先复核上游与需求，再确定高级能力批次。
